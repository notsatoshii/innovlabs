## P0: fix before more learners arrive

**P0-1. A mission can get stuck as "not done" for good, and the reward screen says it worked.**
`src/app/api/course/progress/route.ts:69-85` refuses `done` (409 `steps_missing`) unless every I9 step
of the mission has a `course_xp` row. The client loses unsent steps in several ordinary cases:
- `src/components/course/I9MyTask.tsx:384`: the work-map submit fails with a 5xx or network error, it
  is treated as "not blocking" and `finish()` runs. The step route then answers 422
  `work_map_not_submitted` (`step/route.ts:95-98,158`), so the step is never recorded.
- `I9MyTask.tsx:507-510`: the drill-sheet submit fails without blocking; neither step is sent, and
  the deferred one (`:463-471`) only lives in page state.
- `I9MyTask.tsx:56-66`: `settle()` also resolves when the draft save failed, so the step gets 422.
- Any step that failed on the network: the retry queue (`context.tsx` `useAward`) is lost as soon as
  the learner moves to the next screen or reloads.
After that the learner taps 보상 받기 and `MissionPlayer.tsx:158-163` gets null. The reward screen still
counts the XP up, adds one to the level segments (`MissionPlayer.tsx:185`), says the badge is
"이미 받은 배지예요" (`RewardScreen.tsx:136`, because `newBadges` is `[]`), and offers "다음 미션"
(`RewardScreen.tsx:143`), which then sends them back to the map with `?note=locked`. "다시 보내기" sends
the same request again and gets the same 409. A mission that is not done reopens at its furthest
screen (`m/[id]/page.tsx:51`), so the learner can never get back to the I9 screen, and M1.2 onward
stays locked.
Fix: (a) the progress route returns the missing interaction ids (it already does, in `problems`), and
the player maps them to their screens and offers "이 화면 다시 하기", with a Korean line that names
the step. (b) Open an unfinished mission at the first screen that has an unrecorded I9 instead of
the furthest screen. (c) Only show the reward (badges, segments, next link) after `done` succeeds;
until then show the failure state.

**P0-2. Media placeholder cards show English production notes to learners.**
`src/components/course/MediaCard.tsx:70` renders `media.brief` as visible text, under
"모션 8초 제작 전". These briefs are English notes written for the motion team:
- M1.1 s0: "a calendar flips to 월요일, a report icon fills up over three hours"
- M1.1 s1: "the report splits into a grey part (처리) and a small colored part (판단)…"
- M1.2 s1: "Round 1: paste the 해담리빙 thread, type "이걸 주간보고서로 정리해줘", send…"
- M1.2 s2: "x2: the two outputs, appendix layer"
- M1.3 s1: "a calendar week folds into one sheet…"
- M1.4 s1: "one row "주간보고 쓰기" is pulled apart at a seam…"
- B1 s1: "a one-line ask typed into the learner's assistant, appendix layer…"
The same brief is also used as `alt` / `aria-label` once an asset exists (`MediaCard.tsx:43,55`), so a
screen reader would read English.
Fix: never render `brief`. The placeholder shows only a short Korean line (or nothing). Add a Korean
`alt` field to `Media` for real assets, and have `toMission` (`src/lib/course/content.ts:208`) or
`resolveMissionFor` remove `brief` before the content reaches the browser.

**P0-3. English UI labels (CLAUDE.md rule 1).**
- `src/components/course/LevelMap.tsx:89` "WORLD 0 · 기초". Fix: "월드 0 · 기초" (or "기초 과정").
- `LevelMap.tsx:91` + `src/lib/course/state.ts:176`: the title "레벨 1 · Level 1". No mission has a

## P1: broken or misleading flows

**P1-1. M1.4 shows the wrong 처리/판단 hours right after classifying.** `src/lib/course/slots.ts:97-103`
fills the slots once, on the server, when the page loads. M1.4 s5 ("처리 {{p_hours}}시간, 판단
{{j_hours}}시간 … 이 {{p_hours}}시간이 이 코스가 노리는 시간이에요") and the M1.4 coach line on the reward
come right after the classify step on s4. They show the totals from before classifying, which is
usually only the two M1.1 seed rows, for example "처리 1시간, 판단 1시간". This is the main number of
the level. Fix: compute these slots on the client from `workMap.draft` (with `totals()`), or fetch
them again after the classify step.

**P1-2. A skip-test pass can be shown as a fail.** `src/components/course/SkipTest.tsx:83-86` treats
any 409 as `{ result: "failed" }`. If the first request committed the result but the response was
lost, or the credit insert failed with a 500 after the claim (`skip/route.ts:142-151`), the
"다시 보내기" retry gets 409 `already_taken`. The learner who passed then sees "괜찮아요. 미션으로
가요", and the map later says "통과". Fix: on `already_taken`, return the stored result (and run the
credit again when it is missing) instead of a bare 409.

**P1-3. Reloading or leaving the skip test means a silent fail.** The start row is written once and
never moves (`progress/route.ts:48-63`, `ignoreDuplicates`). The server's time is measured from it
(`skip/route.ts:87-89`), and the test stays on offer after a reload. A learner who reloads, or leaves
and comes back the next day, sees a fresh 3:00 clock. Their next attempt is graded as more than
180 s, so "시간 끝" and a fail, with no warning. Fix: when a start row exists, resume the clock
from it (or say that the time is already running), or let a new start reset the row while it has
no result.

**P1-4. B1 "후보 2번으로 바꾸기" does nothing.** Option `candidate2` of B1 s0 `s1.material` is not read
anywhere (`I9MyTask.tsx:451` checks only `pack`; I10 and I11 check only `own`). The boss still runs on
candidate #1 (`{{candidate1}}`, `drillTask`), and the drill sheet records candidate #1. Fix: build
the branch (a candidate2 slot plus the drill task), or remove the option from the content.

**P1-5. The B1 time-log quest leaves the boss before it is finished.** `I8Timer.tsx:38-41`: on the last
screen of B1, "시간 기록 열기" saves progress and goes to `/app/lab/time-log`. The boss is marked done
only by 보상 받기, which the learner never reaches unless they come back. The level is then not done
and the 하네스 덱 stays closed. Fix: finish the mission (post `done`) before leaving, or open the time
log after the reward screen.

**P1-6. Every failed course call says "연결이 불안정해서… 계속 진행해도 돼요".** `context.tsx:58-65`
returns null for any non-2xx answer, so `NetLine` (`context.tsx:140-144`) shows a network message for
401 (signed out), 409 `mission_locked` / `retry_not_allowed` and 422 `not_verified`. In these cases
"다시 보내기" cannot help, and "계속 진행해도 돼요" leads into P0-1. Fix: pass the status and error code
through; for 401 say to sign in again; for 422 name what is missing; keep the "계속 진행" line for
network errors and 5xx only.

**P1-7. Internal pack ids are shown in labels.** In B1 s2 the doc labels are "재료 보기 (SP-SYN-01-R0)",
"(SP-SYN-01-TPL)", "(SP-SYN-01-T1)". They are rendered raw by `Blocks.tsx:76`. Fix (content): Korean
names such as "지난주 보고서", "양식", "이번 주 대화".

**P1-8. A reload loses choices the learner made in the browser.** `LocalState` (`context.tsx:16-25`)
keeps the B1 choice of material (own/pack), the pasted rounds and the deferred drill step only in
page state, and an unfinished mission reopens at its furthest screen. After a reload in B1:
- The learner who chose "내 재료로" sees the 해담리빙 copy buttons again (I10 and I11 `ownMode`).
- The drill sheet's task can change (the `usingPack` check).
- The deferred step is lost, which is one more way into P0-1.
Fix: save the branch choice in `sessionStorage` (inside try/catch) or in `course_progress.result`.
Keep the pasted outputs in the browser only, as the rule requires.

## P2: polish, integrity, performance

**P2-1. Missions can be finished through the API without playing.** `progress/route.ts:65-67`
accepts any screen number up to the last and `done` on the last screen. It checks only I9 steps, so
M1.2 (which has no I9) can be completed with a single POST, and that unlocks the next mission and
pays the tool card. Fix: require a `course_xp` row for each scored interaction on non-skipped
screens, or at least that the stored `screen` has reached the last screen before `done`.

**P2-2. The combo and 점수 shown in the deck differ from what the server pays.** `I1Sort.tsx:151-158`
counts pieces and retries toward the local streak and points. The server (`score.ts:139-147`) counts
first tries only, and pieces pay nothing. The learner sees "콤보 x2" and points the pill never
matches. Fix: use the server's rule locally, or show the combo from `AnswerResponse.combo`.

**P2-3. Races when answers are fast.** Two quick right answers each read `prior` before the other's
insert, so the combo is underpaid (`answer/route.ts:55-70`). A one-card retry ("#2") can arrive
before the first try is committed and get 409 `retry_not_allowed`, which shows the network line. The
caps limit the damage. Fix: send the answers of one deck in order (a client queue), or compute the
streak in SQL at insert time.

**P2-4. The 코스 tab is not highlighted on /app/course.** `src/components/app/TabBar.tsx:93` matches
`/app/courses` or `/app/courses/…`, and `/app/course` matches neither, so no tab is active anywhere
in the course. Fix: map `/app/course` to the 코스 tab.

**P2-5. M1.1 확인 lists "1번 조각 / 2번 조각 / 3번 조각" instead of the learner's own pieces.** The
content (M1.1 s6 `s6.keep`) has options but no `from: "seed_rows"`, so `I7Choose.tsx:22` does not use
the seed rows. The learner sees generic labels, and a third option even when they saved only two
pieces. Fix (content): add `"from": "seed_rows"`. Check that `validate.ts` accepts the field.

**P2-6. The reward shows the mission total as new XP.** `RewardScreen.tsx:95` shows `+{xp}` for the
mission total, including on a replay of a done mission where 0 was earned. Fix: show what this visit
earned (the total now minus `props.xp` at the start), or label it "이 미션 XP".

**P2-7. A bad URL gives a 500.** `m/[id]/page.tsx:26`: `decodeURIComponent` throws on `%E0`. Fix:
try/catch and redirect to `?note=missing`.

**P2-8. The 모아 sprite sheets are heavier than they need to be.** Each sheet is 9216×256 px, about
9.4 MB once decoded; the five together are about 47 MB, and they are drawn at 48–64 px (132 px on the
reward). The map loads idle (140 KB). The mission page loads idle and think through CSS, and
`preloadMoaSheets` (`MoaSprite.tsx:23-31`) fetches the four reaction sheets (about 570 KB) on mount,
over mobile data. The live server sends them with `Cache-Control: public, max-age=0`, so every visit
checks them again. Reduced motion is handled correctly: only `still.webp` (4.5 KB) and no preload.
Fix: 128 px frames (2x of 64), a versioned filename with `max-age=31536000, immutable`, and load the
reaction sheets after the first interaction instead of on mount.

**P2-9. Accessibility details.**
- `MissionPlayer.tsx:214-221`: the XP pill is a `role="status"` with a fixed `aria-label`, so changes
  to its content are not announced reliably. Fix: drop the aria-label and let the text change.
- `MoaSprite.tsx:60-62`: `role="img" aria-label="모아"` on every screen and in every coach bubble
  (noise for screen readers). Fix: `aria-hidden`, since it is decorative.
- `SpanDoc.tsx:76`: `aria-label` on `<pre>` is not announced. Fix: put the instruction in a visible
  or `sr-only` line above the document.
Checked and fine: #ff4f8b is always used with ink text (about 5.2:1), never with white. White on
#2f5bff is about 5.2:1. Focus rings exist, inputs are at least 16 px, tap targets are at least 44 px.

**P2-10. `{{row_count}}` counts empty rows.** `slots.ts:103` uses `draftRows.length`, so the empty rows
StepWrite keeps are counted ("워크맵에 14줄" when 12 are filled). Fix: count rows with a task.

**P2-11. Replaying a finished mission rewrites live work.** Replaying M1.1 overwrites the `seed-*` rows
in the shared work_map draft. Replaying M1.5 submits the work map again (a new
`work_map_submitted` event). Fix: in a done mission, show the own-work steps read-only, or tell
the learner that saving changes their work map.
